WHERE THIS STANDS in the Work in flight core: createWorkInFlight takes standing (createStanding by default, injectable for tests) and agentPlaces (async () => Record<placeId,{working:number}>, which main fills from agentSessions.placeCounts(); it is awaited once per read, so it must answer from the last session check and must never start one) and adds markStanding(repoId|null|{repoId,placeId?}) and forgetStanding(repoId) to its exports; read() puts the ledger's answer on the view as standing, and the one `log --left-right --format=%m<US>%H<US>%s <seen>...<now>` it makes for a changed place is the only git call this module runs itself (plus `merge-base --is-ancestor` when that page comes back full), with gitArgs()/GIT_ENV re-applied. A ledger that cannot be opened is a listed problem, never a thrown read.
WHERE THIS STANDS core exports createStanding({dataDir,now?,limits?,settings?}) => {read(), mark(repoId|null|{repoId,placeId?}), sample(observations,{landedFor?,record?}), forget(repoId), close(), path, problems()}; helpers listText, whenText, spanText, streamSignature, sketchOf, jaccard, matchStreams are exported for tests and callers. mark takes the panel's own shape, a plain project id or null for every project it has shown as read, as well as the object form that names one folder; createWorkInFlight's markStanding passes all three straight through, which is what IPC work-in-flight-mark sends. sample() takes one observation per repo ({repoId,name,branchTips,places:[{placeId,label,path,fingerprint,oid,items,added,removed,conflicted,paths,aheadOfBase,behindBase,working,lastCommitAt,streams:[{files,readiness}]}]}) and returns {version,at,since,sinceText,moved,landed,landedSubjects,streamsSaved,streamsDropped,streamsReady,still,spinning,blocked,rot,notMoving,rewritten,unreadRepos,byRepo,text,problems}; the view above is built from it. record:false computes without writing. landedFor({repoId,placeId,placePath,from,to,stored}) is the caller's one read-only `log --left-right --format=%m<US>%H<US>%s from...to` through gitArgs()/GIT_ENV, called only for a place whose fingerprint moved, capped at 5 subjects, and returns {from,to,filter,count,more,subjects,oids,rewritten}. Its subjects must already be through redact/hidePrivateText with that project's privatePaths, with a subject that still names a private path dropped whole rather than masked because these are written to disk; `filter` identifies the rules that produced them, `stored` hands back the record on file so a record made under rules that no longer apply is recomputed rather than replayed, and `oids` are the short commits counted, so a repo total counts a commit two folders both reach only once. A `from` the current tip cannot reach, unknown or merely diverged, returns {rewritten:true} and nothing is guessed. A stream's identity is sha1(sorted files) matched to the previous sample greedily, one to one, at Jaccard >= 0.5. The core never reads a repository, never calls a model, never starts a timer, and judges movement by fingerprint, never by modification time. State in dataDir/standing.json (0600, atomic write with file and directory synced, written compactly under a 512 KB cap, oldest samples dropped before any watermark, unreadable file kept as .corrupt-* and history starts again). It stores counts, times, oids, file-set hashes and up to 5 filtered commit subjects per place; no diff text and nothing from a conversation.

SESSIONS SAY WHERE THEY ARE: src/core/sessions/claude.mjs and codex.mjs add titleSource:'user'|'auto'|null and touchedPaths:string[]|null to a RawSession, the paths of files that session edited, at most 200, newest kept. Claude takes them from the tail of ~/.claude/projects/<slug>/<session>.jsonl (96 KB, read forward by remembered offset and size) from `file-history-snapshot` and `file-history-delta` records only, paths and cwd and nothing else parsed; the backup files under ~/.claude/file-history/ hold file contents and are never opened. Codex takes them from `item_completed` items of type FileChange in the rollout tail it already reads, whose `changes` is keyed by absolute path, and reports titleSource:null because its store has no name-source column. Cursor stays null. The transcript tail is read forward by remembered device, inode, size and offset: a file that shrank, or whose inode changed, is read again from its own tail rather than from a remembered offset, and a read that ends mid-line parses nothing past the last newline. Paths that classifyPath() calls private or secret are dropped, and a session in a private folder contributes none. src/core/agent-sessions.mjs matches them against each workstream's files[] for the session's place (at least 2 files or 30% overlap) to fill work.workstream with scope 'session', and fills work.area from the session's own paths when nothing matches. AgentSession gains headline:string|null (project and piece of work, or project and folder) and titleIsAuto:boolean (Claude desktop titleSource 'auto'; absent counts as auto); title keeps the app's own machine-written text and is never hidden.
